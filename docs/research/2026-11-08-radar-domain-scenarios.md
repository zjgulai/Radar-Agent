## 1. 候选术语：先避免概念混用

| 候选术语 | 本轮建议的定义 | 不能混称什么 / 必须验证的边界 |
|---|---|---|
| Radar | PMO 中的 IP/名人合作辅助决策 Agent 与工作台 | 不等于 Echo/VOC，也不等于所有社媒增长能力 |
| 合作对象 | 可能合作的自然人、专家、创作者、名人或拥有授权的 IP 主体 | 对象不等于单个平台账号；不同类型可能需要不同评审流程 |
| 平台账号 | 一个具体渠道中的规范化身份 | 相似名称不是同一个人；账号更名不等于新对象 |
| 证据快照 | 指定来源、时间和权限下取得的一组可引用观察 | 快照不是实时真相；估计不是观测 |
| 背调材料 | 带证据、范围、未知项与需人工核验事项的对象分析 | 不等于身份认证、诈骗断定、健康画像或法律意见 |
| 候选机会 | 一个对象与某个品牌 brief 之间值得复核的合作建议 | 不等于已合作、已购买或预期收入 |
| 合作 brief | 业务目标、市场、品类、对象约束、时程与资源约束的输入 | 未给预算不能伪精确测算回报 |
| 合作计划 | 可审阅的目标、对象、合作模式、执行步骤与风险假设 | 草案不等于预算批准或合同生效 |
| 动态监测事件 | 在批准监测名单和可用渠道内检测到的变化，带观察窗口 | 全渠道是能力目标，不是无授权数据覆盖承诺 |
| 授权材料登记 | 对授权主体、用途、范围、期限及凭证的记录 | 登记不等于法务通过、授权有效或可立即使用内容 |
| 认领 | 有权限的业务成员接手内部候选或任务 | 点击按钮不等于取得对外代表权 |
| 人工复核 | 被授权岗位依据证据对建议、风险或材料作出可记录决定 | Agent reviewer 不等于人工批准 |

业务 owner 确认术语后再写项目术语表；范围或数据设计的真实权衡通过对应节点评审记录管理。

## 2. 三项 PMO 能力必须落到可执行场景

PMO 首页面的 Radar 能力名称是“IP 合作计划制定”“全渠道动态监测”“合作机会识别”。本节是将它们落为场景的建议，不宣称为 PMO 完整原文。完整能力条款和时程应以 PMO 专题研究为准。

### 场景 A：主页链接背调 → 判断与认领 → 授权材料登记

**起点：** BD 在受控飞书群 @Radar 并提供主页链接，或与 Radar 私聊。

**建议过程：**

1. 将平台事件映射为权限明确的请求主体，选择当前品牌与讨论作用域。
2. 解析链接为批准的平台账号；不安全或不支持的链接直接说明原因与可接受输入。
3. 接受请求并创建可追踪任务；用户看到已接受/需要补料，而非等待无回执的长分析。
4. 从批准数据源取得账号和内容快照。读取范围、观察时间和缺失字段写入证据。
5. 输出背调卡片：已知对象/账号、与当前 brief 的关联、观测事实、可复核风险线索、未知、下一步。
6. 用户追问某条证据，系统定位到同一版本的来源；缺少粉丝年龄、地理等字段就明确未知或要求授权提供。
7. 有资源权限的业务成员认领候选；并发认领和重复点击得到确定状态。
8. 登记授权材料，形成待法务/资产 owner 复核的对象；没有材料的记录仍是缺料状态。
9. 工作台呈现同一任务、对象、证据、责任人和授权状态；群中只呈现该群允许的数据。

**终点：** 可复核业务决定 + 责任人 + 材料登记状态，非“自动签约”。

**关键不确定性：** 用户日常是否真的从主页链接发起背调？授权登记是否属于同一次任务？首发合作对象类型是否共享此流程？需要业务访谈验证。

### 场景 B：监测名单 → 有限渠道动态 → 变化解释 → 机会复核

**起点：** 业务批准一组对象/账号和监测规则。

**建议过程：** 明确渠道权限和刷新窗 → 取得快照 → 与可比较快照检测变化 → 去重/合并线索 → 给出证据和时效 → 按规则降噪 → 业务复核为机会/无关/风险线索 → 认领或转交。

**终点：** 可追踪的变化线索及其处理结果。没有访问权限的渠道不写“无变化”；过期数据不写“实时”。

**边界：** 不替代 Source 的采集平台、Signal 的全品牌声量监测、Echo 的消费者 VOC 或 Vicky 的 PR 危机判断。

### 场景 C：业务 brief → 候选比较 → 合作计划 → 复核与效果回流

**起点：** 品牌/BD 提供目标、市场、品类、合作模式、时程与预算约束。

**建议过程：** 识别缺失输入 → 检索批准候选库与证据 → 依据公开评分规则做可解释比较 → 区分预期、假设与已有结果 → 形成可审阅计划 → 法务/品牌/预算复核 → 业务执行并登记结果 → 据实际结果调整规则。

**终点：** 获得业务接受的合作计划与结果记录。Agent 不直接外联、做财务承诺或签署。

**边界：** 效果归因需要内部活动/订单/联盟平台数据；缺少这些数据时只做过程和线索质量分析，不声称营收 ROI。

## 3. 两个入口，一个业务系统

- **飞书**适合请求、追问、通知、认领与有限内部回写。
- **工作台**适合多对象比较、证据浏览、任务状态、监测设置、合作计划编辑与材料治理。
- 两者共用对象、权限、任务、证据、状态和审计契约；不是两个各有事实来源的产品。
- 私聊和群聊不是自动共享知识池；跨作用域内容复制必须遵守资料权限，不能因是同一用户就公开私聊内容。

## 4. 建议核心业务对象（未冻结 schema）

对象关系候选：品牌/工作区 → brief → 候选机会/合作计划；合作对象 ↔ 平台账号；账号 → 证据快照；机会 ↔ 证据/评分版本；对象/计划 → 授权材料；任务 → 会话请求/产物/审计；监测规则 → 观测事件 → 机会复核。

共同约束：

- 每个跨主体对象有工作区/品牌、负责人、来源和版本。
- 一个合作对象可以有多个账号；一个账号的主体关联可以未核验，不自动合并。
- 金额、预测回报和粉丝画像属于各自有来源的字段，不因为显示在一个卡片中而共享证据等级。
- 授权对象需要主体、地域、渠道、用途、期限、文件引用、审核与撤回状态；每个字段含义须对照真实模板讨论。
- 事实、推断、业务决定、操作批准、过程日志和审计证据分开；详细的数据分层在 Main 研究后准确映射。

## 5. 状态机压力测试问题

1. 同一账号更名、被出售或链接失效，是否仍视为同一合作对象？如何记录证据版本？
2. IP 代理人提供授权，实际权利主体不是联系人；授权登记需要哪种证明？
3. 达人同意 organic repost，但未授权 paid ads 或 whitelisting；工作台如何阻止错误使用？
4. 授权期限结束、合同撤回、素材下架，哪个 owner 负责通知和状态同步？
5. 两位 BD 同时认领，能否协作或必须单一主负责人？
6. 群中问题引用私聊报价，哪个结果可以回群？
7. API 只返回最新内容，历史样本不足，如何避免声称持续增长或异常下降？
8. 账户内容公开，但没有 follower demographics，是否仍可出背调？哪些结论必须 unknown？
9. 计划被人工接受，但后来更换 brief、预算或评分规则，旧批准是否失效？
10. 监测线索是负面新闻，Radar 能转交 Vicky/守衡，但不能自己断定法律事实或发布 PR 回应。

## 6. 当前不做的能力

- 自动批量外联、自动谈判、自动付款、自动签约、自动对外发布。
- 从公开内容推断个人健康状况、怀孕/哺乳状态、儿童身份或敏感粉丝画像。
- 用未经支持的“真实性分数”认定对象造假；只能给出可复核异常线索和限制。
- 无权限读取私域账号、群聊历史、联系人或个人资料。
- 首发搭建通用多 Agent 平台、内容工厂、全网 VOC 和完整营销归因系统。
