## 2. 关键来源结论及项目应用

### 2.1 模型不是权限边界

**来源支持（B）：** OWASP 明确要求权限检查在执行组件中进行，而不在模型上下文中；`user_confirmed` 布尔值不足以授权敏感动作。批准需要绑定当前主体、具体工具、目标及参数，并在执行前原子校验/消耗；变更目标或参数须重新批准。[SEC-01 / Tool Security、High-Impact Action Integrity Controls]

**Radar 建议（C）：**

- 飞书事件中的平台身份经服务端校验、映射为项目 principal 后再做工作区/品牌/资源级 RBAC。
- 工作台请求不得自行通过 header 或模型参数指定角色。
- 卡片 action 值只携带业务引用，不携带可被信任的角色、金额批准或授权真值。
- 达人外联、创建实际合作、预算承诺、签署和内容发布默认禁用；将来启用时用精确动作批准对象，不因用户说过“可以自动化”就开放全部动作。
- 权限拒绝、批准、执行结果均有审计事件，审计不含凭证与原始敏感内容。

### 2.2 公开网页是低信任证据，不是指令

**来源支持（B）：** 外部网页、文档、工具结果和历史上下文均可能携带间接提示注入；分隔文字/筛查关键词不构成安全边界。输出及工具参数仍须在执行组件验证。[SEC-02 / Secure Implementation Pipeline]

**Radar 建议（C）：**

- 达人主页、视频描述、评论和外部报告只进入证据/解析通道；不得改变系统指令、工具权限、批准状态。
- 营销事实提取与执行权限解耦；分析器不持有外联、付款或后台管理凭证。
- 引用进入 HTML/Markdown/飞书卡片前分别做安全渲染，不允许任意 HTML、泄漏图片链接或隐式外联。
- 跨用户、群聊、讨论线程、品牌的记忆隔离；私聊内容不会因为同一用户在群里提问而自动公开。

### 2.3 “发主页链接”必须设计防 SSRF 边界

**来源支持（B）：** 仅校验域名不足以阻止 DNS rebinding；需验证解析地址，并确保实际连接只使用经过验证的地址，重试和重定向也必须遵守目的地址策略。网络层隔离是补充防护。[SEC-03 / Domain Name、URL、Network Layer]

**Radar 建议（C）：**

1. 只接受批准的社媒平台资源类型；由 URL 提取规范化的平台与资源 ID。
2. 由具体平台 connector 按固定 API/域名构造请求；不把用户原始 URL 透传为通用 fetch。
3. 默认拒绝非 HTTPS、带 userinfo、IP 字面量、非批准端口、file/data 等协议；短链接须在受控解析器中逐跳核验。
4. 禁止访问环回、私网、链路本地、云元数据与内部业务服务；DNS 检查与实际连接绑定，禁止未复验的跳转和 fallback。
5. 配置大小、超时、响应类型、重试及次数上限。验证失败返回“链接不支持/无法安全获取”，不转为隐蔽浏览器抓取。

上述限制会让部分链接不支持；这是可见产品能力边界，不应为了演示覆盖率关闭安全检查。

### 2.4 一次“拒绝”不是防护有效的证明

**来源支持（B）：** 安全测试必须观察真实工具调用、授权决定与数据变更；最终回复拒绝无法撤销已发生动作。缺少遥测、服务报错、上下文不适用，不能计为成功拦截。[SEC-02 / Grade the Intended Outcome]

**Radar 建议（C）：** 为每个 case 同时保存：输入通道、合法/非法任务、策略版本、批准对象、工具调用轨迹、fixture 状态差异、出站目的地及最终回复。区分 `denied_by_policy`、`needs_review`、`provider_unavailable`、`timeout`、`inconclusive`，不能把后面三类混入“安全通过”。

### 2.5 长任务、重试和停机需要持久化状态

**来源支持（B）：** OWASP 要求限制链深、重试、token 和费用；将异常、超时、熔断与批准行为纳入测试和发布证据。[SEC-01 / Secure Agent Testing、Monitoring]

**Radar 建议（C，具体飞书投递行为由飞书专题研究决定）：**

- 入口先持久化可重放事件/任务，再交给后台执行；不在事件回调中等待完整分析。
- `event_id`、`message_id` 和业务动作幂等键各自解决不同重复问题，不能合并为一个笼统 ID。
- 业务状态与待发消息使用事务 outbox；消息发送超时后进入结果未知/对账状态，不能宣称跨系统 exactly-once。
- 已接受任务即使源平台或模型停机也保留失败原因、重试时间、人工补料入口；不以旧缓存伪装实时数据。
- 数据快照显式显示观察时间、采集时间、覆盖范围、缺失字段和权限类型；未取到数据不等于没有粉丝或没有品牌风险。

## 4. 交付契约

**conclusion：** 官方/标准组织资料支持将执行授权、批准、证据、外联安全及评测分开设计；Radar 应将其作为架构评审和上线闸门的输入（B 支持，项目采用仍为 C 建议）。

**evidence：** SEC-01 至 SEC-03 的具体章节；上文未对来源之外的平台保证做结论。

**assumptions：** Radar 会读取达人公开或经授权资料，接受主页链接，并通过飞书/工作台发出业务建议和内部回写。

**uncertainty：** 具体平台 API、飞书投递细节、内部数据分级/保留制度和部署网络尚需专题研究与批准。

**confidence：** 对权限必须在模型外执行、外部内容不可信和连接时 SSRF 检查有直接来源支持；本项目方案尚无运行验证。

**blocked_actions：** 不得据本笔记批准生产、安全合规、自动外联或处理真实个人数据。

**next_human_action：** 在技术方案节点批准工具/数据/网络的允许范围；在上线节点要求展示真实拒绝、恢复、数据泄漏及误拒绝测试证据。
