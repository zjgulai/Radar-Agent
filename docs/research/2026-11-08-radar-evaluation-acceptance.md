# Radar 从 0 到 1：评测与验收框架草案

- 日期：2026-11-08。
- 状态：C 级建议；尚无真实样本、人审标签或测试结果；**不是可发布声明**。
- 定位：为后续需求、数据、技术及发布节点定义共同验收语言，不抢先冻结未批准的指标阈值。
- 综合口径：以[主计划](../superpowers/plans/2026-11-08-momcozy-radar-zero-to-one.md)§2/5/7和[研究校准](2026-11-08-radar-research-calibration.md)为准：assessment/brief候选/人工决定/认领分离；最低证据不足不可计完成；出站unknown不盲重试；预算耗尽候选failed+原因；浏览器不隐式访问非批准来源。

## 1. 先定义“完成了什么”

Radar 的主验收单位应是 **完成一项可复核的业务任务**，不是“发出一条回复”“模型回答很流畅”或“工作台数字很多”。拟议首个验收任务：用户输入达人主页链接，系统返回带可追溯证据与未知字段的背调材料，业务人员作出候选判断，明确责任人，并将授权材料登记为可审阅对象。

业务 task 的退出状态必须明确：`completed_with_evidence`（取得批准范围内的证据并完成约定输出）、`needs_user_input`、`needs_human_review`、`source_unavailable`、`permission_denied`、`failed`、`cancelled`。人工审查是否通过和外部合作是否成立是不同状态，不合并为“任务完成”。

## 2. 建议的测试数据分层

| 数据层 | 从哪里来 | 允许证明什么 | 不允许证明什么 |
|---|---|---|---|
| 手写 fixture | 无真实秘密/个人资料的固定事件、公开示例或合成业务对象 | 代码契约、幂等、授权、状态机和 UI 行为 | 真实数据覆盖率、业务效用 |
| 机器整理样本 | 授权来源的脱敏样本，由机器提出结构和标签 | 发现字段/案例、形成待审核工作集 | 人工金标与生产准确率 |
| 人审开发集 | 业务 owner 或其授权专家对脱敏任务作出可记录决定 | 开发和调整规则/提示词 | 独立最终质量测量 |
| 人审冻结测试集 | 未被调参使用的独立任务；保留来源、批准记录和版本 | 报告有限范围内的交付质量 | 超出市场/平台/品类/语言的泛化 |
| 授权 live 验收集 | 受控测试群、实际部署、准许的数据和动作 | 真实接入、恢复、跨入口一致性和限定业务接受 | 全量自动化、未经测试的生产流量 |

建议 D11 先批准抽样框、case 类型、标注指南、争议处理和评测成本，再批准样本规模。任何建议规模只是计划，不能替代人审证据。Agent reviewer 的审查不等于人工金标；当前 `human_gold_claim_count = 0`。

## 3. 指标字典候选

所有指标在需求评审中批准分母、来源、排除项、版本和目标。当前不写虚假的“已达 95%”。

| 指标 | 定义与分母 | 应同时报告的限制 |
|---|---|---|
| 业务任务完成率 | 达到对应业务退出条件的任务数 / 范围内合法任务数 | 按平台/任务/语言分层；未知和外部故障单报，不无声剔除 |
| 证据可追溯率 | 具有真实来源和定位单元的事实主张数 / 所有要求引用的事实主张数 | 只挂 URL 不等于引用准确 |
| 证据支持率 | 被来源明确支持的事实主张数 / 由人审抽样检验的主张数 | 样本数、人审者权限、抽样框和争议规则 |
| 字段可得性 | 在指定渠道/权限/时间窗可获得的字段数或账号数 / 明确请求的字段或账号数 | 公开、授权、估计、未知分别报；不能用“填了字段”计真值 |
| 未知处理正确性 | 正确保留未知/时效/权限边界的样本数 / 需处理缺失或未知的样本数 | 错误捏造数量单报 |
| 身份与动作安全 | 越权请求的实际工具/状态变更结果 | 观察服务端拒绝与审计；最终拒绝文本不是充分证据 |
| 合法请求误拒绝率 | 错误安全拒绝的合法任务数 / 适用的合法任务数 | 和合法任务完成率一起看；全部拒绝不是安全胜利 |
| 持久化与幂等 | 重复事件/并发动作/重启恢复 case 的业务变化和消息轨迹 | 跨飞书与数据库不宣称 exactly-once |
| 处理时延 | 入口接收、业务确认、排队、数据获取、分析、回复送达各段时间 | 同时报端到端分位数、失败/超时和缓存；ACK 与结果时延分开 |
| 单任务成本 | 完成/失败一项任务的模型、数据及基础设施边际费用 | 分母为业务任务，不只成功请求；采购固定成本单报 |
| 工作台/飞书一致性 | 同一对象版本在两个入口的状态和权限一致 case 数 / 测试 case 数 | 显示缓存时间与版本；权限不同可见字段不同是正确行为 |
| 业务节省时间 | 对同一任务使用原流程和 Radar 的人工耗时差异 | 记录任务复杂度及人审质量；不能以假定工时宣称 ROI |
| 建议采用与合作转化 | 业务复核通过、候选采纳、后续执行和转化各自的漏斗 | 采用不等于成功合作；无内部转化数据不宣称营收贡献 |

## 4. 最小可证伪 case 集合

下列不是测试结果。每项后续建立固定输入、预期状态/工具行为、来源、实际证据、负责人和版本。

- 支持的平台主页，公开字段存在：给出可追溯背调，粉丝画像缺失仍明确未知。
- 同一对象不同平台账号：账号不凭相似姓名自动合并；待确认的身份关系明确展示。
- 在指定fixture/已测试模式下，同message_id以相同或不同event_id重投不重复创建业务任务，关联原请求；不外推为平台跨系统exactly-once保证。
- 消息编辑/删除、同请求新消息ID、外部发送成功后本地记录前崩溃分别测试；编辑是否受理由需求/平台契约批准，无法可靠查询的发送保留unknown，禁止盲重发。
- 群内不 @Radar：不触发普通会话分析；私聊不依赖 @；机器人自己的消息不形成回复循环。
- 同一群的不同线程同时提问：任务和历史不串；跨群/私聊资料不漏。
- 用户点击背调卡片认领：具有资源权限的主体才可认领；并发结果可解释。
- 点击授权登记：生成材料登记或待审对象，不直接宣告合同生效。
- 变更卡片 action 参数：后端忽略客户端角色/授权真值，对精确对象和版本重新校验。
- 证据过期、平台停机、部分来源不可读：展示实际时间、覆盖和故障；没有数据不等于没有风险。
- 网页提示注入、危险 URL、超大响应：没有越权访问、秘密泄漏、无界资源消耗。
- 已接受任务中途重启：恢复已持久化任务，保留过程和幂等键。
- 工具动作成功但发送回复超时：不重跑不可重复动作；将出站结果标为待对账。
- 用户取消任务：尚未开始/可中断步骤停止；已执行副作用不伪装回滚。
- 报价/合同属于受限资料：普通群聊不得以问答获取；日志不含源文本或凭证。
- 合作计划缺少预算或目标：请求必要信息或给出带假设的草案，不生成伪精确 ROI。
- 机会排序需要行为解释：展示支撑证据、评分版本和限制，不用不可验证的“母婴用户占比”支撑排名。
- 工作台查看页面：不会触发新的采集、分析或指标自增；读操作不污染测量。
- 无数据页面与错误页面：不是全为 0 的正常看板；保留首个可执行补料/重试入口。
- 模型、规则、connector 或权限版本变化：重跑受影响的合同、安全与业务测试。

## 5. 发布证据必须绑定版本

证据包关联同一 `release_id` 与 commit/build 指纹（Git/构建存在后），同时包含：schema、connector、模型、提示词、工具、评分、权限和卡片版本；测试数据清单、case 结果、审计 tail、数据泄漏检查、备份恢复和回滚记录；业务 owner 的明确接受范围。

本地 fixture 通过只能说明本地 fixture 范围。预发可访问也不等于真实写入获授权。任何外部平台异常、未开权限或没有批准的数据依赖，必须作为阻塞/降级项记录，不包装成“基本可用”。

## 6. 节点讨论后需要批准的内容

1. 首发任务、合法/非法输入和完成条件。
2. 数据来源与样本使用/脱敏授权。
3. 人审岗位、标签指南、争议处理与人审记录。
4. 指标分母和分层方法、评测成本、接受线及残余风险。
5. 哪些 case 必须阻塞发布，哪些允许明确降级。
6. 审计/备份/回滚/值班和正式业务签核主体。
