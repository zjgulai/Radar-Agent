1. 把 Radar 定位为**合作决策与协作系统**，而不是全网舆情机器人或不可解释的达人打分器。
2. 首发只覆盖一个业务团队、一个市场、一个重点品类、一个共享决策流程的合作对象类型和一个获准数据路径。
3. MVP 闭环：**主页链接/账号输入 → 可追溯背调 → 关联 brief 的合作判断和轻量计划草案 → 人工复核/认领 → 授权材料登记/待审 → 工作台持续跟进**。
4. 基础版后分别完善 #66 计划、#67 监测、#68 机会排序；不是一次交付全部能力。
5. 飞书与工作台必须同步建设同一条纵向切片；不先建完全部页面再补 Bot，也不把业务状态留在聊天里。

### 1.4 PMO 协作与边界

**C / SRC-PMO-03、OTHER-01：** PMO 将 `creator_id + 授权七元组` 描述为 Radar 的唯一登记源，供 Clone / Paid Media 的 A-Gate 引用；回执样例体现与守衡的权利/claim 检查协作。它是**待落实的跨系统业务协议**，不是本项目已有接口，也不是法律授权授予权。

- Source：评估可用采集契约；每个字段重新核验，不以平台数量证明画像完整。
- Main：工程方法与可能的代码资产参考；复用前查代码、许可、版本、安全和测试，不照搬 10 分钟内存去重。
- Vicky：PR/媒体工作；Expert/Editorial 有重叠，按任务和对外交付责任定归属，不仅按付费与否划界。
- 守衡：经批准 claim/合规规则与复核协作；Radar 不替代法务/监管事务。
- Clone / Paid Media：消费权利状态与限定回执；权限/撤销联调另获批准，首发不自动控制真实投放。
- Echo、Signal、GEO、Daisy：保留协作契约，非首发强依赖；不建设全网 VOC 或通用路由平台。

### 1.5 PMO 四阶与 Main 七阶段不是同一套轴

PMO Stage 1 为基座/SOP，Stage 2 为独立 Bot 双向交互，Stage 3 为高频问题→SOP 验证，Stage 4 为稳定 SOP→工作台固化（C / SRC-PMO-02）。

PMO 写提问 ≥10/周或人工打回 ≥3、返工 <20%，且 Stage 4 要 ≥2 周稳定。Radar SOP 候选记录为 4/周、1 次打回、35% 返工。**这些是 PMO 口径，不是本项目实测，不制造提问以达标，不据此让 Agent 自动改生产政策。**

PMO 的 12-05 背调卡、12-16 寄样/到期催办、12-23 推荐工位是汇报对照。寄样回收 ≥60%、授权到期 <5% 需先明确分母/时间窗/责任与可控性，不能直接作为新系统质量阈值。

Main 七阶段在**每个增量**重复执行；PMO 四阶描述产品成熟度。二者不得强行一一对应。

| 页面 | 核心问题 | 主要动作 |

| 合作对象/账号档案 | 谁、哪些账号、身份关联是否确定 | 查证据、发起背调、提出关联供人审 |

### 2.4 领域边界与状态

以下为 D03/D04/D07/D08/D11 评审用的 **C 级领域候选**，不是已批准 schema。

| 对象 | 语义与关联 | 不等同于 |
|---|---|---|
| 合作主体 `creator` / 平台账号 `account` | 主体可关联多个账号；关联有证据、置信与人工决定；`creator_id` 语义和跨项目唯一性待冻结 | 平台账号ID、姓名相似即同一人 |
| 合作目标 `brief` | 品牌/市场/品类/目标/时间与已知约束，预算可未知，逐次版本化 | 一句笼统“这个人如何”、已批准投放预算 |

| 人工合作决定 `partnership_decision` | `shortlist / reject / request_more_info / defer` 等候选决定，记录理由、操作者、时间、brief/证据版本 | 模型建议、认领、授权或合同 |
| 认领 `claim` | 谁负责后续处理及并发版本规则；与决定分开记录 | shortlist、对外代表权 |
| 计划草案 `plan_draft` | brief/候选/决定关联的目标、理由、步骤、时程与资源假设 | 投入承诺、签约或营收预测 |

- 字段分开标直接观测、授权数据、许可估计、推断、未知；“授权”是获取依据，不等于数据一定正确。
- task过程状态与结果状态分开。建议结果：`completed_with_evidence`、`needs_user_input`、`needs_human_review`、`source_unavailable`、`permission_denied`、`failed`、`cancelled`。`completed_with_evidence`只证明该任务产物满足约定条件，**不证明人工决定已作出或合作生效**。
- 预算/步数/时间耗尽建议退出为`failed`，分别携带`budget_exhausted / step_limit / deadline_exceeded`，保留已获准产物与实际费用；不是自动转为人审成功或自动充值。真正需要人类业务复核时才用`needs_human_review`。恢复需显式新尝试、原任务关联及仍有效的权限/预算。
- 私聊、群、线程与工作区不是共同公开记忆。任务及产物携带`audience_scope`并继承资料ACL；P2P默认不成为工作区共享资料。参与者明确附加/分享时另生成有限投影，记录分享者权限、同意与用途；不能扩大第三方合同/来源的许可。
- 群卡片只发该群可见的最小摘要；私聊报价/合同不自动入群。管理员身份、同一用户、卡片转发或深链均不授予源资源权限；检索、缓存、导出、模型上下文和访问撤销都继承该边界。外部租户/guest首发默认不开放，除非单独评审。
- 被批准的计划改变brief/预算/目标/素材/权利后，是否失效由明确规则处理。

正式术语确认后写`CONTEXT.md`（仅术语）；不可逆、有真实替代与权衡的选择才写ADR。本轮不伪造已批准词典/ADR。

### 4.3 Main 8+3 的按需落地

**C / SRC-MAIN-03：** 八层是采集、存储、打标、指标、分析、呈现、结论、报告；三柱是口径、质量、血缘。这里是契约框架，不要求先建八个服务。

| 层 | Radar 最小落点 | 失败检查 |
|---|---|---|
| 采集 | 每次来源 run、覆盖/空/失败/未运行、时点 | 空响应不等于没有合作风险 |
| 存储 | 观察版本、原始引用、账号关系与保留规则 | 重新抓取不覆盖历史，撤回删除能执行 |
| 打标 | 需要时使用具名标签/版本，样本不足可不做 | 不适用与无法判断分开，模型漂移可查 |
| 指标 | 公式、分母、时间窗、平台限制、版本 | 字段填满不等于正确，异口径不直接比较 |
| 分析 | brief 匹配/规则解释与假设 | 不由关联推因果、不由缺数据推安全 |
| 呈现 | 卡片/工作台相同事实，不同 ACL 投影 | 未知/故障/过期可见，读不改变指标 |
| 结论 | 主张、证据、局限、下一动作、失效条件 | 引用能定位并支持内容，不能只是主页 URL |
| 报告 | 任务产物/获准通知、旧结论失效 | 不持续推送过期/撤回结论 |

`first_seen_at` 区分本系统最早观测与平台发布时间，可从合法保留观察取 min，不假称首次发布时间。空抓留显式记录。“读侧迁移”用于保留观察解释，**不替代业务库 schema 迁移**；业务库按受控版本、兼容窗口、恢复方案演进。

历史/审计追加不意味着永不删除敏感正文；保留权限、删除与撤回要求优先落实，审计只保留依法可留的最小元数据。

### 4.4 权利与 claim 门禁

**B / SRC-FTC-01、FDA-01：** endorsement的material connection、证言真实性及健康宣称需要相应证据与披露；FDA乳房泵资料提示按具体型号/市场/标签审查。FTC FAQ在窄复核中仅经未锁定日期的存档副本读取，不据此确认当前版本；见[条款范围复核](../../research/2026-11-08-radar-source-scope-verification.md)。这里不是法律意见，也不根据单条关键词裁定违规。

设计时将权利主体、合作联系人、合同、素材、用途/渠道/地域/期限/改编/投放/肖像范围、证据、审核、使用记录、撤回/到期拆开。D08评审采用五个独立维度，而非一个“verified”状态：

| 维度 | 候选内容 | 约束 |
|---|---|---|
| 材料受理 `intake_status` | missing/draft/submitted，文档版本与来源 | 上传只证明材料收到；缺料可登记，不通行 |
| 复核 `review_status` | pending/under_review及具名复核结论、复核范围 | 复核了什么必须明确；模型不写法务通过 |
| 有效性 `validity` | 起止时间、撤回、失效原因与来源 | 与复核结果可以同时存在；过去通过可现已过期 |
| 权利范围 `scope` | 主体/代理链、素材、地域、渠道、用途、改编/投放等 | 未知不得默认全球/永久/可投放；排他性也不默认合法值 |
| 具体用途检查 `usage_clearance` | intended-use/素材hash/版本/时间/政策匹配，allow/deny/needs_review | 缺证据默认不允许；首发只保存待审需求，不签发商用放行 |

- “授权七元组”正式定义和与守衡/Clone/Paid Media的协议是D08；不硬凑七字段或把平台账号当合作主体。
- 首发UI/API明确“材料登记，不代表法务通过或授权已生效”；有效权利和实际执行另获组织授权。
- 后续A-Gate执行同时查复核、效期、范围及本次用途；单一grant也不能绕过平台许可或claim审查。
- 到期/撤回需具名owner、通知对象、下游使用台账与升级规则。通知发出不等于已停投；联调需消费者确认/失效状态/审计/超时升级，并批准可实现的传播时限。
- 对外投放、claim放行及法律有效授权不得由模型或普通卡片boolean决定。

## 5. 飞书长连接接入方案

### 5.1 官方机制与项目未核验项

**B / SRC-FS-01、02：** 企业自建应用通过官方 SDK 长连接接收 `im.message.receive_v1`；无须公网入站域名/内网穿透或手写 HTTP challenge。仍需持续运行、出站联网的主机。

- 平台事件处理成功确认期限为 **3 秒**；这是 ACK/handler 期限，不是模型分析或用户收到结果的期限。
- 事件失败可重推；重复可能出现。消息页要求按 `message_id` 去重；通用事件 `event_id` 同存用于排障/其他事件。
- 同应用最多 **50** 条连接；多 client 是随机单点投递，不广播，不依赖会话粘性。本地开发使用独立测试应用，不能分流生产事件。
- **新版 `card.action.trigger` 支持长连接；旧版 `card.action.trigger_v1` 不支持。** 回调不补推；必须及时给同步 toast/受理/冲突/拒绝，慢任务持久化执行。
- 卡片交互、消息更新、延时 token 属不同窗口；选定 API 后锁文档/SDK版本并测试，不把一类规则套给 CardKit/流式卡片。
- 发送/回复支持 `uuid` 的一小时去重窗口（B / SRC-FS-03），仍不是数据库+飞书 exactly-once。

本应用类型/租户地区、归属、机器人能力、权限、版本、可用范围、群资格、订阅和现存连接均未验证；App ID/Secret 不是这些事项的通过证据。

### 5.2 最小权限策略

文本入口核心三项（B / SRC-FS-01，receive 权限表、create 权限表）：

- `im:message.p2p_msg:readonly`
- `im:message.group_at_msg:readonly`
- `im:message:send_as_bot`

`im:resource` 仅在确定需要从飞书下载附件时申请；可首发在工作台导入。群信息/机器人进群事件按确切需求核验权限；群全部消息 `im:message.group_msg` 不默认申请，历史对账若需要它，单独做隐私/范围评审。

首发 Bot 消息不默认需员工 OAuth；工作台 SSO/身份绑定另设计。免审权限、需审核权限、Bot 能力发布与测试版本的生效机制分别核验，不笼统说“一切变更都需审核”。

### 5.3 两条接收路径

**消息：** SDK事件 → 封装/应用/租户检查 → 持久化 inbox → 快速成功确认 → 主体/mention/作用域解析 → 唯一业务任务 → 后台处理 → 事务产物+outbox → 回复/卡片。

**卡片：** SDK回调 → 服务端主体与资源鉴权 → 精确动作/版本/幂等检查 → 短事务执行内部动作或持久化慢任务 → 同步 toast/状态 → 后台后续与消息更新。

数据库不可用不能声称已接受；回调没有补推，用户需看到失败并能安全重试。卡片中不透明引用、版本和签名参数仅防篡改，仍须服务端重新鉴权。

### 5.4 授权 PoC 矩阵（未来任务，本轮未执行）

官方支持与本应用实测分开；以下只在对应D05/D06/D07/D09/D10批准后执行。测试应用/目标用户/群和费用上限必须明确，不能本地另开生产凭证连接分流事件。

| 核验项 | 通过证据 | 不通过/无法判断时 |
|---|---|---|
| 应用归属、事件模式、生效权限、已用集成 | owner提供脱敏配置并批准测试，核对存量连接/使用范围 | HOLD；不能直接切现有模式，另评专用测试应用 |
| 群精确@/P2P、ACK、重推与重连 | SDK版本及真实事件/持久化/响应时间轨迹，非@和自己消息不触发 | HOLD或只做已批准工作台路径；HTTPS回调若需改方向须另批准 |
| 新版卡片回调 | `card.action.trigger`订阅、真实点击、同步toast/失败/过期/重复轨迹 | 保留工作台操作/只读链接；不偷偷添加公网回调端点 |
| 身份与作用域 | 服务端映射、普通群/线程、私聊、工作台登录、转发深链、撤权测试 | 未验证作用域禁用；外部租户/guest默认拒绝，登录降级仍鉴权 |
| 去重/并发/恢复 | 新event_id同message_id、重复点击、并发认领、重启/取消/库故障轨迹 | 不放行该类业务动作；消息编辑是新请求还是不受理由D04/D06冻结 |
| 出站成功/超时/平台去重窗口 | message_id或明确unknown、uuid规则、实际可用查询/权限及外部成功后崩溃测试 | 无已知message_id/可靠查询则unknown+人工；禁盲重发，不许假自动对账 |
| 内容与投递控制 | §5.5策略、收件人/模板批准、泄漏/限速/kill-switch与审计断言 | 不发送；工作台有限可见结果不能伪装飞书已交付 |

- [ ] 分别批准真实接收、数据探测、模型付费和出站发送，不用一次PoC批准覆盖全部。
- [ ] 使用无秘密fixture先验证权限/异常路径；实际日志与模型输入不含凭证或不必要聊天正文。
- [ ] 每项记录pass/fail/indeterminate、能证明/不能证明及fallback；成功截图不能替代业务/安全验收。

### 5.5 统一出站策略（C候选，依赖D07/D10/D11）

所有回复、受理通知、结果卡、提醒和更正都属于外部可见发送，共用`outbound_policy`和outbox；模型不能直接调用发送API。

- 每次发送检查服务端主体/工作区、channel、目标用户/群、audience_scope、内容类、模板版本、来源ACL、校验结果、批准范围、速率/费用与kill switch；执行前复查，撤权后取消未投递项。
- 首发仅允许批准模板的受理/状态/补料、有限证据摘要与工作台深链。模型摘要先过结构化、证据支持、字段/保密校验；需要人工复核时只发待审状态，不把未审内容当结论进群。
- 既有目标群/P2P的请求回复可在明确批准策略内自动投递；其他主动私聊、监测提醒、更正和扩收件人必须分别纳入范围，不能临时拼文案或跨群转发。
- 收件人/内容作用域不可由模型或卡片参数决定；深链不带秘密，不扩大资源访问权限。
- outbox保存动作/策略/模板版本、内容指纹、目标、实际平台ID、attempt和sent/unknown/failed；敏感正文按批准保留期处理，审计不存正文。
- 提供全局/工作区/来源/目标发送暂停与速率上限。消息更新或更正也走同一策略；不能承诺撤销已被看到/转发/使用的影响。

## 6. 架构与分系统实施路线

### 6.1 建议运行拓扑（C）

**Feishu Gateway / API / Worker 三个运行角色 + PostgreSQL 事务事实库 + 私有对象存储。** 一个代码库/业务内核，不预设微服务分仓。

- Gateway 持常驻 SDK 连接，验入与短事务，不运行模型/采集。
- API 提供工作台/命令、身份、资源 ACL、字段裁剪、幂等与版本冲突处理。
- Worker 领取持久化 job，执行批准 connector/模型、证据与 outbox投递/对账。
- 调度器在监测增量引入，可与 Worker 同运行角色；不要先建复杂调度平台。
- 首发可单 client，主备/多活据 RTO与实际测试选；不把单活租约当平台必需条件。
- SSO与应用token分开；秘密在执行边界，不给模型；服务任务保留on_behalf_of/purpose/资源授权，并在执行时复查权限。
- 领域事务/任务记录由业务内核统一写入；安全审计引用task/command/request-id，不能再维护一套独立候选/材料真相。允许与拒绝请求均审计，记录agent/workspace/reviewer/request-id及脱敏主体/查询指纹；没有人工reviewer时明确无，不伪造批准人。

### 6.2 消息与业务的可靠性

| 控制 | 设计要求 |
|---|---|
| 入站去重 | 同存 event_id/message_id；消息任务以 app/tenant/message_id 唯一，不能只做10分钟内存TTL |
| 工作台重试 | 幂等键+请求指纹，同键不同参数冲突；资源更新比较版本 |
| 卡片动作 | 主体/资源/意图/参数/版本核验，命令原子执行；高影响批准一次消耗 |
| 作业恢复 | 租约/心跳/检查点/有界重试/死信；重启恢复，不靠内存历史 |
| 出站 | 业务提交+outbox 同库事务；飞书投递独立；pending/sending/sent/failed/unknown |
| 未知结果 | 超时可能已成功；稳定uuid在适用窗口去重、可行查询对账或人工；不假设平台必能按uuid查询 |

| schema演进 | expand/兼容/受控回填/contract；前向修复/恢复备份，不自动破坏性down |

### 6.3 安全与模型边界

**B / SRC-OWASP-01；工程落点为 C：** 模型输出、网页、简介、评论、工具响应不授予新权限；工具执行端验证主体/范围/schema/额度。高影响批准绑定 actor、tool/action、target/version、规范参数指纹、到期与政策，执行时原子验证并消耗。

平台链接解析为批准资源 ID，由 connector 构造固定网络请求；网络层与实际连接防环回/私网/元数据、DNS变化及跳转。响应字节、调用次数、时间、步数、token和成本有硬限；不要只依赖正则或关键词过滤。

不提供任意 shell、SQL、文件读写、通用fetch或绕过平台限制的cookie登录工具。模型只用当前任务允许工具；确定性步骤优先代码，确需判断处再用模型。

模型供应商/具体型号需以代表任务质量、合法完成、误拒绝、证据支持、部署可达性与成本评审；运行框架不是本项目生产模型选择依据。若选择 Claude，通过当时官方 SDK 文档锁版本/API，不把开发态 Agent SDK 与产品 API混称。

## 7. 评测、验收与发布

### 7.1 分母和证据先于阈值

验收以具名任务类型及`minimum_evidence_set`定义最低可用产物：哪些字段/证据为必需、缺失可否补料/有限完成、哪些缺失使业务无法决定。无brief的assessment不能计入合作机会完成；几乎全为unknown且不足以做约定判断时，不得用“诚实未知”包装完成，转补料/来源不可用或判该切片不可行。

必须同时报告：任务完成；事实引用可定位/支持；字段可得；未知/过期正确处理；合法任务误拒绝；实际越权/网络/状态轨迹；幂等恢复；时延分段；失败也计成本；两入口一致；原流程人工用时；候选采纳/后续合作各自漏斗。

每个工作包在编码前把§6.5失败案例变成固定输入/预期状态和工具轨迹的测试；D11在真实验收前批准任务脚本、人审指南、必需证据、分母、阈值、误拒绝和停止条件。验收报告带task/attempt/request-id、case/源码及版本、原始结果定位、pass/fail/indeterminate/skip、复核人与接受范围。

阈值由D11批准。**20个达人、10秒、80%采纳或95%准确都不是当前承诺**；人审冻结集尚不存在，不能声称通过。

测试数据分层：合成fixture→机器整理待审样本→人审开发集→独立人审冻结集→授权live任务。开发集不作最终独立结果；Agent reviewer不是人工金标。

### 7.2 发布必阻塞案例候选

- 未授权/跨群/私聊/跨工作区读取与字段泄漏。
- 伪造卡片角色/参数、旧版本批准、并发重复动作。
- 危险URL、外部提示注入造成越权或泄密。
- 无证据编造受众、报价、健康状态、权利或ROI。
- 已受理任务重启丢失、重复业务写入、出站超时重跑不可重复动作。
- 撤权后后台仍用旧权限、撤回/到期仍标素材可用。
- 故障/缺遥测/断网计为“成功拦截”；全拒绝称“安全100%”。
- 页面读操作触发采集/分析/业务指标增加，空抓与失败混成0。
- 无恢复演练、无独立接受者、版本证据不一致。

每项后续配固定输入、预期工具/状态、实际轨迹、原因、版本与人类接受者。这里不是安全测试结果。

### 7.3 Main 验收纪律的执行

- 先写检查，再造失败，确认尺子会红；红了检查产品还是测试本身错误。
- 检查三态：pass/fail/indeterminate；跳过明确数量/原因，整体不完整。
- 允许与拒绝请求都须脱敏审计；auth/audit验收包含401/403断言、每请求一条对应审计、非授权字段/凭证泄漏计数为0及其测试范围。该0是待验收断言，当前没有运行结果。
- 总受理任务数=互斥最终结果数+尚未退出的任务数；同一attempt只归一个结果，各结果相加对账。出站sent/unknown/failed另按outbox计，不混为任务完成；重复投递不新增业务任务分母。
- 三个真实输出由业务检查；另一个未为演示特判的输入也跑通。
- 安全看实际工具调用、网络目的地、业务状态与审计，而非最终拒绝文本。
- 人审质量/误拒绝与机制测试并重；fixture只能证明fixture范围。

### 7.4 发布阶梯与审批

| 层级 | 证据/授权要求 |

### 8.6 关键路径与变更规则

**真实任务/MVP → 必需字段/数据许可与权利语义 → 飞书/身份/来源PoC → 可恢复垂直切片 → 独立评测与业务接受 → 获准交付 → 真实运营。**

### 8.7 成本模型，不伪造报价
